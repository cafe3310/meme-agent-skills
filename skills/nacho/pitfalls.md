# 编程语言陷阱与防呆知识库 (Pitfalls & Idiot-proofing KB)

本文件汇总了 TypeScript, Java, Python, C, 和 C++ 中最常见的编程陷阱、边界案例及防御性编程建议。

## 1. TypeScript (TS)
- **`any` 的滥用**：禁用类型检查，导致运行时错误。
  - **防呆**：优先使用 `unknown` 或具体接口。
- **忽略严格模式**：`tsconfig.json` 中关闭 `strict` 会隐藏 `null`/`undefined` 解引用风险。
- **类型断言 (`as`)**：强制转换可能掩盖真实逻辑错误。
  - **防呆**：使用类型守卫 (Type Guards) 或校验库 (如 Zod)。
- **异步错误处理**：遗忘 `await` 或未捕获的 `Promise` 异常。

## 2. Java
- **内存泄漏**：
  - **无界缓存**：`HashMap` 长期持有对象未清理。
  - **静态引用**：`static` 字段持有大对象导致无法 GC。
- **并发隐患**：
  - **非线程安全集合**：在多线程环境下误用 `HashMap` 或 `ArrayList`。
  - **原子性破坏**：错误假设多个同步操作组合后仍是原子的（如 `check-then-act`）。
- **异常吞噬**：空的 `catch` 块掩盖根本原因。

## 3. Python
- **可变默认参数**：`def func(a=[])` 会导致所有调用共享同一个列表。
  - **防呆**：使用 `a=None` 并在函数内初始化。
- **GIL (全局解释器锁)**：限制了 CPU 密集型任务的多线程效率。
- **`is` vs `==`**：混淆标识性 (Identity) 与相等性 (Equality)。
- **资源泄露**：未显式关闭文件或连接。
  - **防呆**：强制使用 `with` 上下文管理器。

## 4. C & C++
- **缓冲区溢出**：越界写入（如 `strcpy`）。
  - **防呆**：使用 `strncpy` 或 `std::string`。
- **内存安全**：
  - **释放后使用 (Use-After-Free)**。
  - **悬空指针 (Dangling Pointers)**。
  - **未初始化变量**：C/C++ 本地变量默认不是 0，导致不可预知的行为。
- **RAII 缺失 (C++)**：手动管理 `new`/`delete`。
  - **防呆**：强制使用智能指针 (`unique_ptr`, `shared_ptr`)。
- **对象切片 (C++)**：值传递导致派生类信息丢失。

## 5. 通用并发陷阱
- **原子性违反**：操作序列被其他线程中断。
- **顺序违反**：假设某个线程总是先于另一个线程完成任务。
- **死锁**：多个锁之间的循环依赖。
